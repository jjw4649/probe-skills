# 보안 점검

## 언제
블랙박스 시험과 같은 검토 대화에서, 그 뒤에 부른다. 고치는 일은 하지 않는다.

## 읽을 것
AGENTS.md '이번 과제'의 (금지) 줄, REQUIREMENTS.md의 권한 관련 R, ENV.md, 소스 코드, git 기록. 읽기 명령(git grep, git log)만 승인 요청한다.

## 점검 일곱 칸
1. 비밀값: API 키, 비밀번호, 토큰이 코드·설정·커밋 기록에 있는가
2. 개인정보 노출: 사용자 화면, API 응답, 로그에 다른 사람의 정보나 쓰지 않는 열(주소, 연락처 등)이 실려 나가는가. 화면에서 숨기기만 하고 응답에는 실려 있는 경우도 찾는다.
3. 권한: 운영자 기능이나 남의 데이터를 막는 검사가 서버 쪽에 있는가, 화면 버튼만 숨긴 것인가
4. 입력 처리: 사용자가 넣은 글자를 그대로 화면에 끼워 넣는 곳(innerHTML 등), 파일 경로를 입력으로 받는 곳, 숫자 범위 검사가 없는 곳
5. 오류 메시지: 내부 경로, 쿼리, 스택이 화면에 그대로 보이는가
6. 외부 전송: 개인정보나 내부 수치를 외부 서비스로 보내는 호출이 있는가
7. (금지) 줄 대조: AGENTS.md의 (금지) 줄마다 지켜졌는지

## 출력
REVIEW.md의 '## 보안 점검' 칸에 표로 적는다.
번호 | 칸 | 위치(파일:줄) | 무엇이 위험한가(비개발자 말 한 줄) | 누가 손해 보나 | 10분 안의 수정 | 지금 고칠지(빈칸, 내가 고름)
문제가 없는 칸도 "확인함, 문제 없음"으로 한 줄 남긴다. 확인하지 못한 칸은 '미확인'으로 쓴다.
ENV.md나 과제 README가 요구한 설정(예: 0.0.0.0 바인딩, 정해진 포트)은 위험으로 세지 않고 "환경 요구, 실제 운영이라면 ○○ 필요"로 한 줄 적는다.

## 멈추는 곳
위험이 큰 순서로 세 줄만 보고하고 멈춘다. 고칠 것은 내가 고르고, 고치는 일은 구현 대화에서 조각 하나로 한다.

## 하지 말 것
- 코드 고치기, 커밋하기
- 비밀값을 찾았을 때 그 값을 대화에 그대로 출력하기 (위치만 쓴다)
- 과제와 무관한 일반 보안 조언 늘어놓기
