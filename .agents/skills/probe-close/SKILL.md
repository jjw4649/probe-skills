# 조각 닫기

## 언제
조각 하나의 구현이 끝났을 때. 네 가지 모양으로 불린다.
- `$probe-close` → 확인 단계
- `$probe-close 통과` → 기록 단계
- `$probe-close 실패: (무엇을 눌렀더니 무엇이 보임)` → 원인 단계
- `$probe-close 인계` → 인계 단계 (새 대화 직전, 조각 3개쯤 지나서, 제출 문서 쓰기 전)

## 확인 단계
읽을 것: REQUIREMENTS.md의 이번 조각 R과 성공 기준, DATA.md 확인 숫자(조각 1이면).
1. 문법 검사(node --check 또는 그 언어의 검사)와 첫 화면 확인(웹이면 curl, 웹이 아니면 실행 명령 한 번)을 승인 요청한다. 서버는 켜지 않는다. 꺼져 있으면 켜는 명령과 포트만 알려 준다.
2. 내가 눌러 볼 클릭 3개. 각각 "무엇을 누르면 → 무엇이 보여야 함(성공 기준 문장)". 셋 중 하나는 예외 성공 기준이다.
3. 계산 기능이면 한 사람 따라가기 예시 1건: 입력값 → 중간값 → 결과.
4. 조각 1이면 화면에 나와야 할 확인 숫자를 DATA.md에서 옮겨 적는다.
5. 이 환경에서 확인할 수 없는 것은 '미확인'으로 표시하고 대체 확인 방법 하나를 제안한다.
멈추는 곳: 10줄 이내로 보고하고 멈춘다. 커밋하지 않는다.

## 기록 단계 (`통과`)
1. 이번 조각에서 바꾼 파일만 git add 한다. 비밀값 파일(.env 등), 설치 폴더(node_modules 등), 큰 데이터 사본은 넣지 않는다. 첫 커밋이면 .agents 폴더와 기록 파일(INTERVIEW, DATA, REQUIREMENTS, AGENTS, ENV, DECISIONS)도 함께 넣는다.
2. "조각 N (R 번호) (이름)"으로 커밋하고 `git log --oneline -3`만 보여 준다.
3. DECISIONS.md에 이번 조각 결정 한 줄(결정 | 누가 | 버린 대안 | 이유 | 약점). 없으면 쓰지 않는다.
4. 내가 '미확인'이라고 말한 항목이 있으면 커밋 메시지 끝에 "(미확인: ○○)"를 붙인다.
보고는 3줄: 커밋 해시, 기록한 줄, 다음 조각 이름.

## 원인 단계 (`실패`)
코드를 고치지 않는다. 원인 후보 3개 이내와 각각을 확인하는 방법만 준다. 고칠 방법은 내가 고른다. 같은 증상으로 두 번째 실패면 조각을 더 작게 나누자는 제안을 같이 한다.

## 인계 단계 (`인계`)
코드를 고치지 않는다. HANDOFF.md를 기존 틀대로 **새로 덮어쓴다**(덧붙이지 않는다). 완료된 R과 무엇으로 확인했는지, 커밋 목록(git log --oneline), 미확인, 다음 할 일 1개, 열린 결정, 실행 방법. 내가 확인하지 않은 것을 확인했다고 쓰지 않는다. 다 쓰면 "읽고 고친 뒤 /new 하세요" 한 줄만 보고하고 멈춘다.

## 하지 말 것
- 내가 '통과'라고 하기 전에 커밋하기
- 내 눈으로 보지 않은 것을 '통과'나 '확인됨'으로 쓰기
- 파일 전체나 diff 전체를 대화에 출력하기
