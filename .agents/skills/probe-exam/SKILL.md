# 서술형 대비

## 언제
동결과 검증이 끝난 뒤, 제출 전 한 번. 코드는 고치지 않는다.

## 읽을 것
소스 코드(파일 목록과 각 파일의 머리 부분), DECISIONS.md, DATA.md, REQUIREMENTS.md, HANDOFF.md, REVIEW.md(있으면).

## 1. ARCHITECTURE.md (파일로 저장, 40줄 이내)
- 파일마다 맡은 일 한 줄
- 데이터 흐름 한 줄: 입력 → 정리 → 계산 → 저장 → 화면 (해당 없는 칸은 뺀다)
- 한계선과 경계값을 처리하는 곳(파일과 함수 이름), 설정값이 모여 있는 곳
- 쓴 알고리즘의 표준 이름과 한 줄 설명 (예: 군집화 k-means, 가까운 곳부터 잇는 휴리스틱)
- DECISIONS.md의 큰 결정이 코드 어디에 들어가 있는지 한 줄씩
- 빈 입력, 외부 실패, 한계선 초과 때 화면에 무엇이 보이는지

## 2. 대화에만 쓰는 대비 메모 (비개발자 말로)
1. 예상 질문 6개와 답 재료 3줄씩: 결정의 약점 / 누가 정했나 / 범위와 합의 / 검증과 미확인 / 모듈 구조 / 알고리즘과 가정
2. 결정을 '누가'로 나눈 목록: AI 선택지·내가 고름 / AI가 정함 / 팀장 확인 후 내가
3. 확인된 것과 미확인 목록 (무엇으로 확인했는지 포함)
4. 현실과 다를 수 있는 가정 3개와 각각의 대응
5. 화면의 안내·오류 문구 전부

답 재료는 기록 파일에 있는 사실만 쓴다. 기록에 없으면 "기록 없음"이라고 쓴다.

## 멈추는 곳
ARCHITECTURE.md를 저장하고 대비 메모를 보여 준 뒤 멈춘다. 커밋은 내가 확인한 뒤 지시한다.

## 하지 말 것
- 코드 고치기
- 기록에 없는 이유를 지어내기 ("아마 ~때문" 금지)
- 답안 문장을 완성해 주기 (재료만 준다. 서술형은 내가 쓴다)
