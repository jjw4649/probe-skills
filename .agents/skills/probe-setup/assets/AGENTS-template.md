# AGENTS.md
## 일하는 방식
- 나는 비개발자다. 어려운 용어는 한 줄로 풀어서 설명해라.
- 새 대화를 시작하면 REQUIREMENTS.md, DATA.md, HANDOFF.md, DECISIONS.md를 먼저 읽어라.
- 한 번에 한 조각만, 바꾸는 파일은 2개까지. 더 필요하면 조각을 나누자고 먼저 말해라.
- 화면 구조·저장 방식·범위·권한 방식·계산(판정) 방식 같은 큰 결정만 장단점과 함께 선택지 2개로 묻고, 작은 세부(파일 나누기, 함수, 라이브러리, 색·배치)는 묻지 말고 네가 정해 DECISIONS.md에 '누가: AI가 정함'으로 남겨라.
- 보고는 10줄 이내: 한 일 → 확인 결과 → 미확인 → 가정한 것 → 내가 할 일.
- 내가 답하지 않은 질문이 있으면 다음 보고 첫 줄에 다시 물어라.

## 확인과 기록
- 조각을 시작하면 코드를 쓰기 전에 성공 기준과 계획 5줄(바꿀 파일, 쓸 데이터와 열, 확인 방법)을 보여 주고 내 확인을 기다려라.
- 조각이 끝나면 문법 검사(node --check 등)와 curl로 확인하고, 내가 눌러 볼 클릭 3개를 성공 기준과 함께 주고 멈춰라. 셋 중 하나는 예외 성공 기준이다.
- 계산 기능이면 '한 사람 따라가기'용 예시 1건(입력값 → 중간값 → 결과)을 같이 보여 줘라.
- 내가 '실패: 증상'이라고 하면 코드를 고치기 전에 원인 후보 3개와 각각의 확인 방법을 먼저 보여 줘라.
- 내가 '통과'라고 하면 이번 조각에서 바꾼 파일만 커밋하고 git log를 보여 줘라. 확인 못 한 것은 '미확인'으로 표시해라.
- 결정은 DECISIONS.md에 결정·누가·버린 대안·이유·약점으로. 알고리즘은 표준 이름으로 적어라. 오류가 있었으면 '오류: 증상 → 원인 → 내 지시' 한 줄을 더해라.
- HANDOFF.md는 쓸 때마다 덮어써라. 덧붙이지 마라.

## 품질 기준
- 빈 입력, 잘못된 형식, 외부 실패를 처리하고, 대체 결과에는 대체라고 표시해라.
- 서버는 내가 새 터미널에서 직접 켠다. 너는 명령과 포트만 알려 줘. 0.0.0.0 바인딩, API 키는 코드와 커밋에 쓰지 마라.
- 과제의 핵심 기능을 빼거나 바꾸는 선택지는 "팀장 확인 필요"라고 먼저 표시해라.

## 데이터 규칙
- 데이터는 DATA.md '사용 계획'에 적힌 파일과 열만 써라. 다른 파일이나 열이 필요하면 쓰기 전에 물어라.
- 정리 규칙(제외, 중복 제거)은 코드 한곳에 모으고, 제외한 개수를 사유별로 화면에 보여라.
- 숫자 한계값은 설정값 한곳에 모으고, 팀장에게 듣지 않은 값은 '가정'으로 표시해라.
- 같은 입력이면 같은 결과가 나오게 해라(무작위를 쓰면 시드 고정).
